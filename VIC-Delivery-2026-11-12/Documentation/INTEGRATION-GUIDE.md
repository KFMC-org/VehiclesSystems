# دليل دمج حزمة VIC

لا تنفذ هذه الخطوات على الإنتاج مباشرة. استخدم فرع دمج ونسخة قاعدة اختبار، وخذ نسخة احتياطية وفق سياسة الفريق.

## 1. مراجعة أولية

1. راجع `FILE-INVENTORY.md`, `DATABASE-INVENTORY.md`, `DEPENDENCIES.md`, و`EXCLUSIONS.md`.
2. تأكد أن نسخة SmartFoundation المستهدفة توافق المشروع المرجعي `C:\GitHub\laaaaaaast` أو أعد فحص Patches.
3. تحقق من الكائنات المشتركة المذكورة في `DEPENDENCIES.md` ومن تعريف `dbo.Idara`.
4. عالج عدم اتساق `userID_FK` و`RequestID_FK` قبل نشر Views/Procedures المتأثرة.

تنبيه: المقارنة البرمجية الأساسية تمت مع `C:\GitHub\laaaaaaast`، وليس مع فرع `master` القديم في VehiclesSystems. راجع `TARGET-REPOSITORY-STATUS.md`؛ لا تطبق الحزمة مباشرة على ذلك الفرع قبل تحديث خط الأساس أو اعتماد الدمج اليدوي.

## 2. ترتيب دمج الملفات

1. انسخ محتوى `SmartDynamicFields` البرمجي إلى نفس المسارات في `SmartFoundation.UI`، ولا تنسخ ملف README إلى المشروع إن لم ترغب.
2. راجع `VehicleFiles/REMOVE-LEGACY-VIC-FILES.md` واحذف ملفات VIC القديمة المذكورة بعد التأكد من عدم وجود تعديلات موازية عند الفريق.
3. انسخ الملفات التطبيقية داخل `VehicleFiles` محافظًا على المسارات النسبية؛ لا تنسخ ملف تعليمات الإزالة إلى المشروع إن لم ترغب.
4. ادمج `VehicleController.Base.cs` بالمقارنة إذا كان لدى الفريق تعديل موازٍ.
5. طبّق أو ادمج يدويًا Patches بالترتيب:
   - `001_sf-form_VIC_actions.patch`
   - `002_sf-drawer_VehicleDetails_styles.patch`
   - `003_Reports_VIC_printing.patch`
5. لا تستبدل أي ملف مشترك كاملًا بسبب Patch.

أمر فحص Patch قبل التطبيق من جذر المستودع:

```powershell
git apply --check <path-to-patch>
```

إذا فشل الفحص بسبب تغير السطور، ادمج المقاطع يدويًا وراجع أسماء الدوال والتواقيع والسلوك.

## 3. ترتيب إنشاء قاعدة البيانات

الترتيب المقترح على قاعدة اختبار فارغة من VIC:

1. `Database/Schema/001_Create_VIC_Schema.sql`
2. `Database/Tables/001_VIC_Tables.sql`
3. تأكد من وجود `dbo.Idara`، ثم `Database/IndexesAndConstraints/001_VIC_Indexes_And_Constraints.sql`
4. ملفات `Database/Views` بعد حل عدم الاتساق الموثق.
5. ملفات `Database/StoredProcedures` بعد حل عدم الاتساق الموثق.
6. ملف `Database/Triggers`.
7. ادمج يدويًا مقتطفات `Database/SharedGatewayPatches` داخل البوابات المشتركة، مع الحفاظ على مسارات الأنظمة الأخرى.
8. راجع اسم قاعدة الهدف ومالك Job ثم ثبّت `Database/AgentJobs/001_VIC_AutoGenerateMaintenanceOrders.sql` إذا كان SQL Server Agent جزءًا من البيئة.

ملف القيود جامع؛ لا تنفذه قبل توفر الجداول المشتركة التي تشير إليها Foreign Keys. لا توجد بيانات Seed ضمن الحزمة.

## 4. فحوص البناء والواجهة

1. نفذ `dotnet restore` ثم `dotnet build` للحل أو مشروع MVC.
2. نفذ اختبارات الحل الحالية.
3. افحص JavaScript عبر `node --check` للملفات الجديدة والمعدلة.
4. افتح صفحات: قائمة المركبات، التفاصيل/Drawer، العهد، النقل والموافقات، الصيانة الدورية، الصيانة العامة، الإسقاط، المخالفات، والتقرير الشامل.
5. تحقق أن الصلاحيات هي نفسها المعادة من بوابات النظام وليست صلاحيات واجهة فقط.
6. اختبر البحث والفرز والفلاتر والطباعة والتقارير.

## 5. اختبارات SmartDynamicFields

- الصيانة العامة: فتح الإضافة، إضافة/حذف حتى 16 عطلًا، رفض الصف الفارغ، حفظ `p09` كـJSON، ثم فتح التعديل وتحميل الأعطال وحفظها.
- الإسقاط: إضافة/حذف الأسباب، رفض الفارغ، التحقق من حد 800 حرف، وحفظ النص النهائي في `p06`.
- تأكد من عدم تحميل JavaScript الخاص بصفحة في صفحة أخرى، ومن ترتيب تحميل محرك المكوّن قبل ملف الصفحة.

## 6. اختبارات قاعدة البيانات

- شغّل السكربتات على قاعدة اختبار فقط وراجع أخطاء الربط قبل الانتقال.
- تحقق من أعداد الكائنات مقابل `DATABASE-INVENTORY.md`.
- اختبر مسارات البوابات: 38 مسار DataLoad و9 مسارات CRUD، كل مجموعة منفصلة.
- اختبر صلاحيات المستخدم العادي والمدير، ولا تعتمد على مستخدم مدير فقط.
- اختبر Job يدويًا في بيئة اختبار ثم راقب عدم توليد أوامر مكررة قبل تفعيل Schedule.

## 7. GitHub

بعد نجاح المراجعة والاختبارات فقط:

1. أنشئ فرعًا جديدًا في نسخة العمل الخاصة بمستودع VehiclesSystems.
2. في الحالة الحالية للمستودع، أضف محتوى الحزمة كمجلد تسليم مستقل للمراجعة؛ لا تضعه كـoverlay مباشر على جذر التطبيق القديم.
3. راجع `git diff --staged` بحثًا عن أسرار أو ملفات خارج VIC.
4. أنشئ Commit عاديًا وافتح Pull Request؛ لا تستخدم Force Push أو Reset.

لم تُنفذ هذه الخطوات في مرحلة إعداد الحزمة، انتظارًا لموافقة المالك.
